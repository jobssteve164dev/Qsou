# 数据流架构设计

## 修复后的正确架构

### 数据流顺序
```
爬虫采集 → 数据清洗/NLP处理 → ES索引(主存储) → 向量化 → Qdrant存储(辅助存储)
```

### 详细流程

#### 1. 爬虫数据采集
- **位置**: `crawler/qsou_crawler/`
- **输出**: 原始爬取数据（标题、内容、URL等）

#### 2. 数据处理管道
- **位置**: `data-processor/tasks.py` → `process_crawled_data`
- **功能**: 
  - 数据清洗和验证
  - NLP处理（分词、实体识别、情感分析）
  - 质量评估和去重

#### 3. ES索引（主存储）
- **位置**: `data-processor/tasks.py` → `update_search_index`
- **功能**:
  - 存储完整文档数据
  - 建立全文搜索索引
  - 支持复杂查询和聚合
- **触发**: 数据处理完成后立即触发

#### 4. 向量化与Qdrant存储（辅助存储）
- **位置**: `data-processor/tasks.py` → `generate_embeddings`
- **功能**:
  - 生成文档向量嵌入
  - 存储到Qdrant用于相似度搜索
  - 仅存储向量+元数据，不存储完整文档
- **触发**: ES索引成功后自动触发

## 架构优势

### 1. 正确的存储层次
- **ES作为主存储**: 存储完整文档，支持全文搜索
- **Qdrant作为辅助存储**: 仅存储向量，支持语义搜索

### 2. 数据一致性保证
- ES索引成功后才会触发向量化
- 避免了数据不一致的问题
- 确保搜索结果的完整性

### 3. 性能优化
- ES负责快速全文搜索
- Qdrant负责高精度语义搜索
- 两者互补，提供完整的搜索体验

## 修复的关键问题

### 1. 原问题
- 先存储到Qdrant，再"同步"到ES
- 颠倒了主存储和辅助存储的角色
- 导致数据不一致和统计错误

### 2. 修复方案
- 先索引到ES（主存储）
- ES成功后触发向量化到Qdrant（辅助存储）
- 确保数据流的正确顺序

## 配置要点

### ES索引配置
- 新闻: `qsou_news`
- 公告: `qsou_announcements`
- 通用: `qsou_documents` (别名)

### Qdrant配置
- 集合: `investment_documents`
- 向量维度: 384
- 模型: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`

### 批处理配置
- 默认批次大小: 32
- 支持并行处理
- 自动错误重试
