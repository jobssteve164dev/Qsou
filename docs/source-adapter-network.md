# QSou 来源适配器网络设计

## 1. 目标

来源适配器网络的目标不是“爬虫进程能运行”，而是持续建立一条不失真的情报链：每份正式文档都来自已登记来源、可回到不可变原始响应，并能明确知道由哪个适配器版本、哪次运行产生。

这条网络必须同时满足：

- 可扩展：新增来源只增加一份来源契约、一个适配器和对应测试。
- 可升级：解析规则有独立版本，升级后保留旧证据、旧文档版本和运行历史。
- 可管理：来源、实现、调度、游标、运行指标和前台状态使用同一套来源身份。
- 不失真：入口响应、首页快照或进程退出码都不能冒充“详情已采集成功”。
- 可恢复：抓取、归档、解析和索引分层；解析失败不丢原始响应，索引可以从标准文档重建。

## 2. 单一事实链

```text
SourceRegistry（来源契约）
  → AdapterRegistry（1 个来源 = 1 个版本化适配器）
  → SourceAdapterSpider（统一下载执行器）
  → RawEvidenceDownloaderMiddleware（解析前归档）
  → SourceAdapter（发现详情、解析标准文档）
  → DataProcessingPipeline（身份、版本、证据关系、索引状态）
  → adapter_runs / source_cursors（运行和连续性事实）
  → adapter_run_requests（逐源手动触发与重启恢复）
  → API / 数据资产页面（统一管理与真实状态）
  → 私人搜索 / 证据查看 / JSONL 导出
```

任一阶段失败都保留已经成立的上游事实。例如详情解析失败时保留详情原始响应，但不会生成伪标准文档。

## 3. 适配器契约

每个适配器实现以下稳定边界：

| 能力 | 输入 | 输出 |
|---|---|---|
| `initial_requests` | 来源配置、上次游标 | 一个或多个入口请求 |
| `discover` | 已归档入口响应 | 去重后的详情引用 |
| `detail_request` | 详情引用 | 详情请求 |
| `parse_document` | 已归档详情响应、详情引用 | 合格标准文档或明确无产出 |
| `cursor_candidate` | 本轮合格文档 | 带适配器版本的连续性检查点 |

适配器不能自行绕过统一下载器访问网络，不能绕过证据归档直接写数据库，也不能把首页、列表页或 robots.txt 直接作为正式情报文档。

生产执行器只加载 `source_adapter` 一个 Spider，并使用可识别、稳定的 QSou 采集身份。随机浏览器身份、代理占位和反检测伪装不属于生产链；它们会破坏访问行为的可复现性。去重只依据来源文档身份与内容哈希，不能按标题丢弃文档，因为不同来源或不同主体可能发布相同标题的独立事实。

## 5. 运行状态口径

每一轮至少保存：入口总数、入口成功数、详情发现数、详情获取数、文档产出数、证据归档数、失败数、开始/完成时间、适配器版本和游标前后值。

统一下载基座为公告大文件保留 900 秒完成窗口，并把实际超时值写入运行指标；该窗口来自生产节点对 35 MiB 级官方公告的真实下载验证，避免短超时触发整份文件重复传输。容器的 4 GiB 上限中预留系统余量后，采集进程内部上限为 3.5 GiB。超时和内存门槛用于容纳真实结果，不能用来把慢下载提前改写成应用失败。

- `running`：来源当前正在执行。
- `healthy`：至少一个入口成功，所有已发现详情均成功获取并产出合格文档，且文档已经实际登记入库。
- `degraded`：入口成功，但存在详情获取/解析缺口，或没有产生合格详情文档；部分成功不能显示为完全健康。
- `failed`：采集进程失败或没有任何入口成功。
- `cancelled`：运行被明确中止。
- `not_started`：来源已登记，但尚无运行记录。
- `stale`：最近一次成功运行已经超过两倍计划周期，不能继续显示绿色。
- `queued`：用户已经发起逐源采集，等待采集器原子认领。
- `authorization_required`：适配器身份已登记，但没有允许自动采集的有效通道。

原始证据数量不参与健康判定。保存了一份 robots.txt 或入口页，只能证明响应已经归档。

## 6. 游标与升级连续性

当前游标采用“最近窗口重访 + 稳定来源文档身份去重”的保守策略：

- 每轮重新访问最近的公告接口或新闻列表，避免站点补发、置顶和排序变化造成遗漏。
- `source_document_id` 确定同一来源文档身份，内容哈希确定版本；重复访问不会制造重复文档。
- 只有 `healthy` 运行才推进游标；失败或零产出不推进。
- 适配器升级必须增加版本号。调度器发现登记版本与最近运行版本不一致时立即执行新版本，不等待原计划周期；新版本仍回看最近窗口，不从旧游标之后盲目跳过。

后续若某个来源提供可靠的序号、分页 token 或更新时间接口，可以在该适配器内部升级游标形状，但不得改变统一状态和证据边界。

新闻正文适配器可以声明 `content_container_patterns`，由统一 HTML 解析基座只提取来源正文容器；正文容器不存在时才回退到标准 `article/main` 语义区域。容器规则属于适配器版本的一部分，修改后必须提升版本，防止导航、登录和页脚文字混入正式情报。上交所公告使用其官方 `big5.sse.com.cn` 内容镜像获取原始 PDF，避开会返回脚本挑战页的静态下载入口；该路径仍属于上交所登记域名，不使用浏览器伪装或挑战绕过。

图解报道不能因为正文缺少长文本而被丢弃，也不能用未经验证的 OCR 文本冒充原文。统一解析基座会识别正文容器内的原始图片，把报道登记为 `image_story`，逐张下载并归档图像证据；只有已发现图像全部归档成功，该轮来源才允许进入 `healthy`。可搜索文本只使用来源标题、来源摘要和“图解/图片数量”这一结构事实，图像内容仍以原始证据为准。

## 7. 迭代闭环

一次适配器迭代按以下顺序完成：

```text
保存失败响应或固定样本
  → 新增失败复现测试
  → 修改单一来源适配器并提升版本
  → 运行全体适配器契约测试
  → 远程构建 Collector 制品并审计依赖/大小
  → 精准发布 Collector
  → 等待该来源产生终态
  → 核对详情发现、文档产出、证据和搜索结果
```

只修到“请求不报错”不算闭环；只修到“进程成功退出”也不算闭环。

## 8. 正式搜索边界

通用 HTML 快照仍作为原始证据保留，但不进入正式搜索语料。正式搜索只使用由版本化来源适配器生成并关联详情证据的标准文档。这样即使某个来源页面结构变化，系统也会显示降级，而不会用首页导航文字制造“仍然有数据”的假象。

## 9. 当前能力边界

- 已实现九个来源的一对一适配器、来源级调度、版本、运行账本、游标、证据、标准文档、搜索与管理状态闭环。
- 数据资产页可逐源发起立即采集；请求持久化、重复请求去重、采集器重启自动重排，结果回写同一运行账本。
- 人工采集请求在每个计划来源结束后优先认领，不需要等待整轮计划来源全部跑完。
- 当前九个来源均启用生产调度；SEC EDGAR 通过季度目录发现最新每日索引，不依赖停更 feed 或受限页面抓取。
- 公告 PDF 使用统一 PDF 文本抽取；扫描件 OCR 尚未加入正式链路，无法抽取时会如实降级。
- 多数来源的条款仍为 `review_required`，不表示已经取得再分发许可；SEC EDGAR 单独登记为 `automated_access_allowed`，仍必须遵守官方身份声明、速率和安全政策。
- 当前游标保证保守重访和版本去重，但还没有外部独立对账源来证明每个来源的历史窗口绝对完整。
- SQLite 与共享卷适合当前单节点部署；多节点写入前必须升级目录服务与对象存储，但不得改变证据身份和适配器契约。
