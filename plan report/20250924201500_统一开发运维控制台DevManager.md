# 规划蓝图：统一开发运维控制台（Dev Manager）
*   **状态**: [进行中]

## 1. 核心目标与验收标准
- 以自研后端服务统一管理本地/开发环境的所有模块与进程，提供跨平台（Win/macOS/Linux）一致体验与可视化 UI。

### 验收
- [ ] `dev-manager/` 后端可启动，提供 API：列举/启动/停止/重启/状态、日志尾、健康检查
- [ ] `config/dev_services.yaml` 列出受管服务（API、前端、爬虫、Celery、ES、Qdrant、Redis等）
- [ ] 前端 `web-frontend` 新增 Dev Console 页面，可展示服务状态与一键操作
- [ ] 具备跨平台兼容（以 Python+psutil/subprocess 实现进程管理）

## 2. 技术方案
- 后端：FastAPI + uvicorn，psutil 管理进程，tail 日志，CORS 开放本地前端
- 配置：YAML 驱动，命令与环境变量可覆盖
- 前端：Next.js 页面 `/monitor` 或新增 `/dev/console` 集成服务卡片

## 3. 任务分解
- [进行中] 新建 `config/dev_services.yaml`
- [未开始] 创建 `dev-manager` 后端骨架与公共进程管理模块
- [未开始] 实现 API（列表/操作/日志/健康）
- [未开始] 前端页面骨架与 API 对接
- [未开始] 文档与 QUICK_START 更新

## 4. 风险与应对
- Windows 与 *nix 进程差异：使用 psutil + Popen，避免 shell 特殊语法
- 端口占用：提供自动检测与 kill（交互确认）
- 日志大小：限制 tail 行数，必要时 gzip 轮转
